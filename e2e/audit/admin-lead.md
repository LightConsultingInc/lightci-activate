## Fixes applied (typecheck clean for touched files; `eslint` clean except pre-existing unused imports)

Frontend (hot-reloaded, verified live):
- `frontend/components/admin/policy-view.tsx`: read `settings.policyVersion` (was `usagePolicyVersion`, so the panel always said "Version 1"); stop sending client-side version bumps; show `changed <date>`.
- `frontend/components/admin/teams-view.tsx`: member count reads `members` (API field; was `memberCount`, never rendered); import-groups toast uses `{groups, created, linked}` (was `imported`); invite toast now distinguishes `invitation: 'failed' | 'skipped'` with the WorkOS detail instead of always "Invited".
- `frontend/components/admin/marketplace-view.tsx`: mode vocabulary `hidden|available|auto` (was `auto_installed`, so the select showed raw `auto` and saving fell back to `available`). `MODE_LABEL` in `mission-control/governance-view.tsx` gained `auto`.
- `frontend/components/lead/lead-console.tsx`: `subject` accepts the summary object or a string; skill links use `slug` (was `name` → 404); the drawer's assignee list is fetched with `X-Activate-Org: <escalation.orgId>` (was `usePeople()` → 500/empty when the lead has no client selected, wrong org otherwise).
- `frontend/hooks/mc/types.ts`, `frontend/hooks/mc/use-mc.ts`: types for the above (`policyVersion`, `members`, `auto`, invite result, import result).

Backend (**requires API restart**; `tsc` clean):
- `api/src/orgs/org.controller.ts` + `org.service.ts`: accept `auditNote` and record it as `meta.note` on `policy.updated`/`boundary.updated`/`org.updated`; drop legacy `usagePolicyVersion` from incoming settings; `listTeams`/`listPeople` return `[]` for a null org (unscoped lead) instead of a TypeORM 500; setup `keys.detail` says `invalid` not `missing` for a rejected key.
- `api/src/ops/escalations.controller.ts`: null-scope list returns all orgs' rows (was 500); assign validates against `e.orgId` (was request scope → 403 for unscoped/cross-client leads); audit rows carry `e.orgId`.
- `api/src/ops/lead.service.ts` (+ `ops.types.ts`): `subject` is `{id, name, type, slug?}`; assignees who are LightCI leads are resolved (Builder escalation showed unassigned although assigned to Zain).
- `docs/api-contract.md`: Deviations entry added.
